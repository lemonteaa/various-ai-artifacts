Yes, that comment is absolutely true. Implementing Fog of War (FoW) on the CPU (JavaScript loop over grid tiles) is expensive and complex to make smooth. However, moving that logic to the GPU (GLSL Fragment Shader) is incredibly efficient because the shader runs in parallel for every pixel on the screen.

Instead of calculating "is grid tile X,Y visible?", the shader simply asks for every pixel: "Am I close to a unit?" This is an $O(1)$ operation per pixel (relative to map size) handled by the graphics card, which is designed exactly for this.

Here is a complete, standalone R&D Proof of Concept. It demonstrates a **Shader-Based Dynamic Fog of War**.

### Key Features of this PoC:
1.  **GPU Accelerated:** Visibility is calculated entirely in the Fragment Shader.
2.  **Dynamic:** The "holes" in the fog follow the units in real-time.
3.  **Soft Edges:** Uses `smoothstep` to create natural gradient falloffs for sight radius.
4.  **Integration Ready:** The system simply takes an array of `{position, range}` data and passes it to the GPU via Uniforms.
5.  **Debug Mode:** A visual toggle to see the actual "mask" generated by the shader.

```html
        import * as THREE from 'three';
        import { OrbitControls } from 'three/addons/controls/OrbitControls.js';

        // --- Configuration ---
        const MAX_UNITS = 50; // GLSL Uniform Array Size limit (easy to change)
        const MAP_SIZE = 100;
        const FOG_HEIGHT = 0.5; // Slightly above ground to avoid Z-fighting
        
        // --- Global State ---
        let scene, camera, renderer, controls;
        let fogPlane, fogMaterial;
        let raycaster, mouse;
        const units = []; // Stores { mesh, targetPosition, speed }
        let isDebug = false;
        let isAnimating = true;

        // --- GLSL Shaders ---
        // This is where the magic happens. The logic is GPU-side.

        const vertexShader = `
            varying vec2 vUv;
            varying vec3 vWorldPosition;

            void main() {
                vUv = uv;
                // Calculate world position of the vertex
                vec4 worldPosition = modelMatrix * vec4(position, 1.0);
                vWorldPosition = worldPosition.xyz;
                gl_Position = projectionMatrix * viewMatrix * worldPosition;
            }
        `;

        const fragmentShader = `
            uniform vec3 uUnitPositions[${MAX_UNITS}];
            uniform float uUnitRadii[${MAX_UNITS}];
            uniform int uUnitCount;
            uniform bool uDebugMode;

            varying vec3 vWorldPosition;

            void main() {
                float visibility = 0.0;

                // Iterate through all units to check proximity
                // In a production game with hundreds of units, use a Texture Lookup or Compute Shader
                for (int i = 0; i < ${MAX_UNITS}; i++) {
                    if (i >= uUnitCount) break;

                    vec3 unitPos = uUnitPositions[i];
                    float radius = uUnitRadii[i];

                    // Calculate distance on the XZ plane (ignoring Y)
                    float dist = distance(vWorldPosition.xz, unitPos.xz);

                    if (dist < radius) {
                        // Calculate falloff (Soft edge)
                        // smoothstep(edge0, edge1, x) returns 0.0 if x <= edge0 and 1.0 if x >= edge1
                        float contribution = 1.0 - smoothstep(radius * 0.7, radius, dist);
                        
                        // We take the max visibility (overlapping lights don't make it brighter, just visible)
                        visibility = max(visibility, contribution);
                    }
                }

                if (uDebugMode) {
                    // Debug mode: Red = Hidden, Green = Visible
                    gl_FragColor = vec4(visibility, visibility, 0.0, 1.0);
                } else {
                    // Production mode: Black with varying Alpha
                    // If visibility is 1.0, alpha is 0.0 (fully transparent)
                    // If visibility is 0.0, alpha is 1.0 (fully opaque fog)
                    gl_FragColor = vec4(0.05, 0.05, 0.1, 1.0 - visibility); 
                }
            }
        `;

        function createFogOfWar() {
            // Create a large plane covering the map
            // We rotate it -90 deg on X to lay flat, or just use geometry
            const geometry = new THREE.PlaneGeometry(MAP_SIZE, MAP_SIZE);
            geometry.rotateX(-Math.PI / 2);

            // Uniforms initialization
            const initialPositions = new Array(MAX_UNITS).fill(new THREE.Vector3(0,0,0));
            const initialRadii = new Array(MAX_UNITS).fill(0);

            fogMaterial = new THREE.ShaderMaterial({
                vertexShader: vertexShader,
                fragmentShader: fragmentShader,
                uniforms: {
                    uUnitPositions: { value: initialPositions },
                    uUnitRadii: { value: initialRadii },
                    uUnitCount: { value: 0 },
                    uDebugMode: { value: false }
                },
                transparent: true,
                side: THREE.DoubleSide,
                depthWrite: false // Important: allows seeing "through" the fog if we want layers, 
                                  // but here we use it simply as a top-layer mask
            });

            fogPlane = new THREE.Mesh(geometry, fogMaterial);
            fogPlane.position.y = FOG_HEIGHT;
            scene.add(fogPlane);
        }

        function addUnit(position = null, range = null) {
            if (units.length >= MAX_UNITS) {
                console.warn("Max units reached for this shader demo");
                return;
            }

            const radius = range || (10 + Math.random() * 10);
            // Random pos if none provided
            const pos = position || new THREE.Vector3(
                (Math.random() - 0.5) * MAP_SIZE * 0.8,
                1.5, // Sit slightly above fog
                (Math.random() - 0.5) * MAP_SIZE * 0.8
            );

            // Unit Visual Representation
            const geometry = new THREE.ConeGeometry(1, 3, 8);
            geometry.rotateX(Math.PI / 2); // Point forward
            const material = new THREE.MeshStandardMaterial({ 
                color: 0x00bcd4, 
                roughness: 0.3,
                metalness: 0.8
            });
            const mesh = new THREE.Mesh(geometry, material);
            mesh.position.copy(pos);

            const ringGeo = new THREE.RingGeometry(radius - 0.2, radius, 32);
            ringGeo.rotateX(-Math.PI / 2);
            const ringMat = new THREE.MeshBasicMaterial({ color: 0x00bcd4, transparent: true, opacity: 0.2, side: THREE.DoubleSide });
            const ring = new THREE.Mesh(ringGeo, ringMat);
            ring.position.y = -1; // Below the cone
            mesh.add(ring);

            scene.add(mesh);

            units.push({
                mesh: mesh,
                targetPosition: null,
                speed: 0.2 + Math.random() * 0.1,
                sightRange: radius
            });

            updateStatusBar();

        function updateUnits() {
            // Move units towards targets
            units.forEach(unit => {
                if (unit.targetPosition) {
                    const direction = new THREE.Vector3().subVectors(unit.targetPosition, unit.mesh.position);
                    const distance = direction.length();
                    
                    if (distance < 0.5) {
                        unit.targetPosition = null; // Arrived
                    } else {
                        direction.normalize();
                        unit.mesh.position.add(direction.multiplyScalar(unit.speed));
                        // Rotate unit to face target
                        const lookTarget = unit.targetPosition.clone();
                        lookTarget.y = unit.mesh.position.y; // Keep level
                        unit.mesh.lookAt(lookTarget);
                    }
                }
            });
        }

        function updateFogUniforms() {
            // Sync JS data to GPU Uniforms
            // This is the heavy part on CPU side, but passing simple arrays is cheap
            const positions = fogMaterial.uniforms.uUnitPositions.value;
            const radii = fogMaterial.uniforms.uUnitRadii.value;

            for (let i = 0; i < MAX_UNITS; i++) {
                if (i < units.length) {
                    const unit = units[i];
                    positions[i].copy(unit.mesh.position);
                    radii[i] = unit.sightRange;
                } else {
                    // Reset unused slots so they don't affect visibility
                    positions[i].set(0, -1000, 0); 
                    radii[i] = 0;
                }
            }

            fogMaterial.uniforms.uUnitCount.value = units.length;
        }

        // --- Interaction ---

        function onPointerDown(event) {
            // Only move if we clicked on the canvas, not UI
            if (event.target.closest('.panel')) return;

            // Normalize mouse coords
            mouse.x = (event.clientX / window.innerWidth) * 2 - 1;
            mouse.y = -(event.clientY / window.innerHeight) * 2 + 1;

            raycaster.setFromCamera(mouse, camera);

            // Raycast against a mathematical plane at y=1.5 (unit height)
            const planeZ = new THREE.Plane(new THREE.Vector3(0, 1, 0), -1.5);
            const target = new THREE.Vector3();
            
            raycaster.ray.intersectPlane(planeZ, target);

            if (target) {
                // Check if we clicked a unit to select it, or ground to move
                // For simplicity in this PoC: Click ground -> Move ALL units to that point (swarm)
                // Or click ground -> Move nearest unit?
                // Let's implement: Move all units to the clicked location to demonstrate performance easily
                units.forEach(unit => {
                    unit.targetPosition = target;

                // Add a visual marker for click

            }

        function createClickMarker(pos) {
            const geo = new THREE.RingGeometry(0.5, 0.8, 16);
            geo.rotateX(-Math.PI / 2);
            const mat = new THREE.MeshBasicMaterial({ color: 0xffffff });
            const mesh = new THREE.Mesh(geo, mat);
            mesh.position.copy(pos);
            mesh.position.y = 0.1;
            scene.add(mesh);
            
            // Fade out effect
            const startTime = Date.now();
            const duration = 500;

                const elapsed = Date.now() - startTime;
                if (elapsed < duration) {
                    const scale = 1 + (elapsed / duration) * 2;
                    mesh.scale.set(scale, scale, scale);
                    mesh.material.opacity = 1 - (elapsed / duration);
                    mesh.material.transparent = true;
                    requestAnimationFrame(animateMarker);
                } else {
                    scene.remove(mesh);
                    geo.dispose();
                    mat.dispose();
                }
            }
            animateMarker();
        }
```

You found a classic JavaScript reference trap! It is not a GPU bug, but a CPU-side data handling issue.

**The Cause:**
When I initialized the uniform array, I used `Array.fill(new THREE.Vector3(0,0,0))`.
In JavaScript, `fill` with an object fills the array with **references to the exact same object**, not unique copies.

Here is what was happening in your game loop:
1.  You add a Unit. The loop updates `positions[0]` to the unit's location.
2.  Since all 50 slots in the array point to that *same* memory address, `positions[1]` through `positions[49]` instantly update to that location too.
3.  The loop continues for the "empty" slots (indexes 1 to 49). Because they are unused, the code executes the `else` block: `positions[i].set(0, -1000, 0)`.
4.  Since they are the **same object**, this overwrites the actual unit's position.
5.  The result: The GPU receives `(0, 0, 0)` (or `(0, -1000, 0)`) for every unit, causing the fog hole to stay at the center.

**The Fix:**
We need to create an array where every slot is a unique `Vector3` object. We also need to ensure Three.js knows the uniform data has changed every frame.

Replace the `createFogOfWar` and `updateFogUniforms` functions with this corrected code:

```javascript
// --- CORRECTED FUNCTIONS ---

function createFogOfWar() {
    const geometry = new THREE.PlaneGeometry(MAP_SIZE, MAP_SIZE);
    geometry.rotateX(-Math.PI / 2);

    // FIX 1: Create an array of UNIQUE Vector3 objects
    // Instead of fill(), we map to create new instances for every slot
    const initialPositions = Array.from({ length: MAX_UNITS }, () => new THREE.Vector3());
    const initialRadii = new Array(MAX_UNITS).fill(0);

    fogMaterial = new THREE.ShaderMaterial({
        vertexShader: vertexShader,
        fragmentShader: fragmentShader,
        uniforms: {
            uUnitPositions: { value: initialPositions },
            uUnitRadii: { value: initialRadii },
            uUnitCount: { value: 0 },
            uDebugMode: { value: false }
        },
        transparent: true,
        side: THREE.DoubleSide,
        depthWrite: false
    });

    fogPlane = new THREE.Mesh(geometry, fogMaterial);
    fogPlane.position.y = FOG_HEIGHT;
    scene.add(fogPlane);
}

function updateFogUniforms() {
    const positions = fogMaterial.uniforms.uUnitPositions.value;
    const radii = fogMaterial.uniforms.uUnitRadii.value;

    // We need to flag the array for update so Three.js uploads it to GPU
    let dataChanged = false;

    for (let i = 0; i < MAX_UNITS; i++) {
        if (i < units.length) {
            const unit = units[i];
            
            // Only update if position actually changed (optimization)
            if (!positions[i].equals(unit.mesh.position)) {
                positions[i].copy(unit.mesh.position);
                radii[i] = unit.sightRange;
                dataChanged = true;
            }
        } else {
            // Reset unused slots to deep underground so they don't affect map
            // Note: Since we fixed the array initialization, this now only affects 
            // the specific index 'i', not the whole array.
            if (positions[i].y !== -1000) {
                 positions[i].set(0, -1000, 0);
                 radii[i] = 0;
                 dataChanged = true;
            }
        }
    }

    fogMaterial.uniforms.uUnitCount.value = units.length;
    
    // FIX 2: Explicitly tell Three.js to update this uniform
    if (dataChanged) {
        fogMaterial.uniforms.uUnitPositions.needsUpdate = true;
        fogMaterial.uniforms.uUnitRadii.needsUpdate = true;
    }
}
```

1.  **Initialization:** Used `Array.from(..., () => new THREE.Vector3())` to ensure every slot in the uniform array is a separate object.
2.  **NeedsUpdate:** Added `.needsUpdate = true` inside the loop. Sometimes Three.js optimizes by assuming array data hasn't changed if you don't reassign the whole array. This flag forces the data to be sent to the GPU.

Paste these two functions into your existing code, and the fog should correctly follow your units

```javascript
fogPlane.position.y = MAX_TERRAIN_HEIGHT + 1.0;
```
*Note:* This means the "fog" is technically a ceiling. It works fine for RTS, but units standing on tall mountains might look like they are poking their heads through the fog. This is usually acceptable.

**The Advanced Fix (Shader Modification):**
If you have a heightmap texture of your terrain, you can pass that texture to the shader and displace the fog vertices vertically based on the heightmap, making the fog "hug" the terrain surface exactly. (This is significantly more complex).

### 4. Scaling (Sight Radius Units)
Since you are using floating points, ensure your `sightRange` matches your world scale.
*   If 1 World Unit = 1 Meter, and a tank has a 50m view range, pass `50.0`.
*   If your map coordinates are small (e.g., 0.0 to 10.0), and you pass a radius of `50.0`, the whole map will be lit up.
*   **Check:** Verify that the visual ring size in your engine roughly matches the "hole" size in the fog.

### 5. "Explored" vs "Visible" (The Shroud)
The PoC implements **Visible** Fog (The "Fog of War").
*   **Visible:** You can only see what your units currently see. If a unit moves away, that area instantly becomes black again.

Most RTS games have two layers:
1.  **Fog of War (Visible):** Black areas where you have no units.
2.  **Shroud (Explored):** Gray areas where you *have been* but don't have units currently. You see the terrain, but you don't see enemy unit movements.

**Limitation:**
The shader approach above is stateless. It calculates visibility *right now* based on unit positions. It **cannot** remember where you were 5 minutes ago.

**To add "Explored" (Gray Shroud):**
You would need a **Second Plane** (or a more complex shader setup).
1.  Layer 1 (Bottom): **Shroud**. This requires a Render Target (a texture you draw to). When a unit visits an area, you "paint" white onto this texture permanently. It doesn't clear when units leave.
2.  Layer 2 (Top): **Fog**. The dynamic shader we just built. It cuts holes in Layer 1.

**My Recommendation:**
Start with just the **Visible** fog (Layer 2). If your game design strictly requires "Explored" areas (graying out the map), that requires "Ping-Pong buffering" or Frame Buffer Objects, which is a much bigger step up in WebGL complexity.

### Summary for Integration
1.  **Map is infinite?** Move the fog plane X/Z to match camera every frame.
2.  **Map has hills?** Raise the fog plane Y to `MaxHeight + buffer`.
3.  **Units are flying?** The current shader ignores Y-height distance. It treats a plane at 0m height and a plane at 100m height as having the same XZ distance to the ground pixel. (If you need true 3D line-of-sight, the shader math changes to `distance(vWorldPosition, unitPos)`).

You are in a good spot! The fact that you don't have tiles actually makes the GPU approach faster because you don't have to calculate which tile is which; you just feed coordinates.
